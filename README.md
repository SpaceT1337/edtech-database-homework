## Задание 1. Концептуальная модель

### Основные сущности
* **Пользователи (`users`)** — единая таблица для всех участников системы (студенты, преподаватели, администраторы). Роль разграничивается с помощью поля `role`.
* **Курсы (`courses`)** — образовательные программы, создаваемые преподавателями.
* **Уроки (`lessons`)** — учебные материалы, лекции и модули, входящие в состав конкретного курса.
* **Записи на курсы (`enrollments`)** — таблица-связка, отражающая процесс обучения.
* **Отзывы (`reviews`)** — оценки и комментарии студентов к пройденным курсам.

### Связи между сущностями
* **Преподаватель — Курсы (1-to-Many):** Один пользователь с ролью преподавателя может создавать и вести множество курсов. Каждый курс закреплен за одним конкретным преподавателем.
* **Курс — Уроки (1-to-Many):** Один курс включает в себя множество уроков. Каждый урок принадлежит строго одному курсу.
* **Студенты — Курсы через `enrollments` (Many-to-Many):** Один студент может записаться на несколько курсов, а на один курс могут записаться множество студентов. Связь реализована через промежуточную таблицу записей.
* **Студенты и Курсы — Отзывы через `reviews` (Many-to-Many):** Студент может оставлять отзывы к разным курсам, а курс — получать оценки от множества студентов. Отношение реализовано через отдельную таблицу с ограничением уникальности пары «студент — курс».

## Задание 4. Частые запросы к базе данных
Для платформы спроектированы следующие типовые сценарии запросов:
1. Получение списка всех активных курсов с указанием ФИО преподавателя и стоимости.
2. Вывод расписания уроков для конкретного курса, отсортированных по порядковому номеру (`serial_number`).
3. Проверка статуса прохождения курсов конкретным студентом (история записей и флаг завершения `is_completed`).
4. Подсчет средней оценки каждого курса на основе оставленных отзывов студентов.
5. Вывод списка всех студентов, записанных на определенный курс, для контроля успеваемости.
